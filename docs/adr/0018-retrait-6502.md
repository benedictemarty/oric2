# ADR-18 — Retrait du 6502 dans Phosphoric

- **Statut** : ratifiée 2026-05-09 (Phase 0 programme état-de-l'art)
- **Date** : 2026-05-09
- **Décideurs** : bmarty (utilisateur), Claude Code (assistance senior)
- **Contexte** : DEC-1 actée. Programme « remise au top de l'état de l'art ».
- **Conformité moratoire** : oui — dossier d'instruction écrit (≥ 2 alternatives chiffrées), recommandation senior tracée. Implémentation différée Phase 1 mais campagne de validation préalable bloquante.

## Contexte

Le cœur 6502 historique de Phosphoric coexiste avec le 65C816 nouvellement implémenté pour le projet Oric 2. Cette cohabitation est encapsulée par une vtable `cpu_core_vtable_t` (`include/cpu/cpu_core.h`) mais pèse :

- ~10 K LOC dupliquées (cpu6502.c 166 + opcodes.c 572 + addressing.c 113 + tests test_cpu.c 1103 + test_cpu_core.c 199, ainsi que ~9 K dans cpu65c816 / opcodes 65C816).
- Surface de tests doublée pour comportements largement équivalents.
- Risque de divergence de comportement sur futur ajustement (e.g. ADR-11 sémantique mode E).

Le 65C816 mode E (E=1) est conçu pour être strictement compatible 6502. Klaus Dormann passe, ROM Oric 1 boote, suite Oric 1 verte sur 6502 actuel. La cohabitation perpétuelle ne se justifie pas techniquement.

DEC-1 fixait l'échéance « avant Sprint 3 » — déjà dépassée (Sprint 3.c v0.4 actif).

## Options envisagées

### (a) Retrait net post-validation **[retenue]**

Suppression de cpu6502.c, opcodes.c, addressing.c, vtable 6502, tests test_cpu.c, après campagne de validation explicite du 65C816 mode E sur la suite Oric 1 actuelle.

- ✅ Surface de maintenance Phosphoric divisée par ~2.
- ✅ Source unique de vérité comportementale (mode E hybride ADR-11).
- ✅ HDL ULX3S devra implémenter un seul cœur.
- ⚠️ Dépend du critère go/no-go : 541 tests verts + bench ≤ 5 % + boot interactif ROM 1.0/1.1.
- ⚠️ Si bug subtil non couvert apparaît post-retrait, restauration coûteuse (git revert facile mais test à reconstruire).

### (b) Flag compile-time `-DLEGACY_6502`

Maintient les deux cœurs disponibles via flag de build. Build par défaut = 65C816 only.

- Coût maintenance résiduel des 2 cœurs (compilation conditionnelle, tests deux configs).
- Justifié par redoute de retour arrière, qu'aucun signal technique ne supporte.
- **Écartée** : sécurité illusoire, dette résiduelle pour gain marginal.

### (c) Cohabitation perpétuelle

Documenter formellement que les deux cœurs cohabitent ; choix runtime via CLI `--cpu`.

- Régression-protection maximale.
- Dette de maintenance permanente.
- Deux suites de tests à maintenir éternellement.
- **Écartée** : aucun bénéfice après validation 1.B.

## Décision

**Option (a) — retrait net post-validation.**

### Plan d'exécution Phase 1

1. **Étape 1.A — Décrochage des types partagés** (~½ j) : extraire `memory_t`, `cpu_irq_source_t`, `cpu_flags_t`, `IRQF_*` de `cpu6502.h` vers `include/cpu/cpu_types.h` neutre. Tous consommateurs (debugger, trace, profiler, emulator.h, tests) incluent `cpu_types.h`.
2. **Étape 1.B — Campagne de validation 65C816 mode E** (~1 j, **bloquante**) : bascule défaut `emu.cpu_kind = CPU_KIND_65C816`. Migration `test_klaus_dormann.c`, `test_oric_boot_dual.c`, `test_paravirt_demo.c` vers mode E. Audit shifts/rotations zp/abs M=0 (dette identifiée BACKLOG).
3. **Étape 1.C — Suppression effective** (~½ j, après go) : `src/cpu/cpu6502.c` (166 LOC), `src/cpu/opcodes.c` (572), `src/cpu/addressing.c` (113), `include/cpu/cpu6502.h`, `cpu_core_vtable_6502`, `CPU_KIND_6502`, `tests/unit/test_cpu.c` (1103, redondant). Réécriture `test_cpu_core.c` (199) en `test_cpu816_core.c`.
4. **Étape 1.D — Traçage** (~½ j) : ce document, BACKLOG, CHANGELOG.

### Critère go/no-go (1.B → 1.C)

- **541 tests verts** (suite complète à cpu_kind=65C816 par défaut).
- **Bench performance ≤ 5 %** (contrainte CLAUDE.md §7).
- **Boot interactif ROM Oric 1 1.0 et 1.1** (5 minutes BASIC + LIST + RUN + boucle).
- Si l'un échoue : on diagnostique, on ne supprime pas. Étape 1.B peut être ré-itérée.

## Conséquences

### Positives

- Surface de maintenance Phosphoric ~÷2 (suppression ~2 K LOC + tests redondants).
- Source unique de vérité comportementale (mode E + ADR-11).
- HDL ULX3S simplifié : un seul cœur à porter.
- Cohérence avec ADR-01 (CPU 65C816 cible).

### Négatives

- Toute régression imprévue post-retrait nécessite git revert + reconstruction tests.
- CLI `--cpu 6502` retirée (no-op avec warning ou suppression). Apps externes scriptées doivent être adaptées (impact négligeable, projet jeune).
